## Transformations

### 1. `card_id` normalization

Set codes recognized: `OP`, `EB`, `ST`, `PRB`, `P`.

| Form | Example | Action |
|------|---------|--------|
| Already normalized | `OP01-042`, `ST13-003`, `P-001` | Use as-is |
| 5-digit pack-prefixed | `ST13003` | Insert dash before last 3 → `ST13-003` |
| 5-digit pack-prefixed | `OP07029` | Insert dash before last 3 → `OP07-029` |
| Set code only | `OP01`, `ST10` | Quarantine (no number) |
| P-card | `P001` | Dash-format → `P-001` |
| No set code match | `OnePieceTCG2nd...` | Filtered upstream (M6.5-T2) — never reaches silver |

Implementation: `is_valid_card_id()` in `src/tcg_platform/defs/silver_transform.py`.
Tries the raw input against the cardlist first; falls back to regex
extraction `(OP\d+|EB\d+|ST\d+|PRB\d+|P\d+)(?:-\d+)?` for unnormalized
forms. Extracted to module level for testability (per the M6.5-T1
scraper emitting already-normalized card_ids, the previous closure logic
quarantined every valid record).

### 2. `title` field capture

`title` is captured from the bronze item-page parser and forwarded into
the silver schema. Two real-data issues surfaced during smoke (fixed in
M7-T2-update):

- **NaN title from Spark's `toPandas()`.** `toPandas()` converts `None`
  to `NaN` (a float) for str-dtype columns. The writer's `is None`
  check missed NaN, and the `fillna` loop's `dtype == object` check
  didn't match pandas' new `str` dtype. Result: `title` got stored as
  `float64(0.0)`, and re-runs of the collision check saw `0.0 != ''` →
  spurious `_1` files on every re-run.
  Fix: `pd.isna(v) → ""` before passing into the writer; the `fillna`
  loop now matches `object`, `str`, and `string` dtypes.

- **Float sentinel in legacy files.** Pre-fix silver files have
  `title=0.0` (float). `_extract_identity_tuple` treats `0.0` and `0`
  as `""` for collision-check tolerance.

### 3. Quarantine logic

Records that fail `is_valid_card_id` are written to
`tcg-silver/quarantine/{region}/{event_id}.parquet` (per-item layout
after the M7-T2-update refactor). Records with valid card_ids land in
`tcg-silver/data/{region}/{event_id}.parquet`.

### 4. Collision check

Per-item-id layout means multiple re-scrapes of the same eBay item can
target the same `{event_id}.parquet` path. The writer resolves collisions
via the `(sold_date, event_id, title)` tuple:

- All three match → overwrite in place (re-scrape dedupe)
- Any differ → find next free `{event_id}_1.parquet`, `_2`, etc.

`sold_date + event_id` is already unique in normal operation (eBay never
reuses an item_id for the same sale date); `title` is included as a
robustness check to dedupe re-scrapes where title text varies slightly.
