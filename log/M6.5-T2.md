# M6.5-T2 Log: Skip Listings Without a Recognizable Card ID

**Date:** 2026-06-05
**Status:** Complete

## Summary

The UK and DE item-page parsers' shared `_normalize_card_id()` helper fell
through to `return t, None` when the title contained no set code matching
`(OP|EB|ST|PRB|P)\d+(?:-\d+)?`. That returned the entire normalized title
as `card_id` with empty `card_version` — non-card listings like 3-card
bundles and DON energy cards ended up in bronze, SQLite, and
`silver/quarantine` with garbage identifiers.

## Real cases from 2026-06-05 run

| eBay item_id | What the listing actually was | What got written as `card_id` |
|--------------|-------------------------------|-------------------------------|
| `168427997844` | 3-card bundle ("...2nd Anniversary Winner 3 Cards Luffy...") | `OnePieceTCG2ndAnniversaryWinner3CardsLuffy...` (whole normalized title) |
| `257501709731` | DON energy card ("...DON Card Carrying On His Will Foil...") | `PSA10DONCardCarryingOnHisWillFoilOnePieceTCG` |

Both polluted bronze parquets, SQLite `fact_events`, and silver
`quarantine/` with rows that are not One Piece cards at all.

## Fix

`_normalize_card_id` returns `('', None)` on no match; each parser returns
`[]` when `card_id` is empty, skipping the listing at parse time so it
never reaches bronze. No `(card_id, source_url)` SQLite row, no MinIO
parquet, no silver-quarantine row — gone at the source.
