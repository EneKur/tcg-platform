## What was done

### M6.5-T1: eBay Scraper Redesign — Per-Region Parsers (COMPLETE)
Replaced the shared `ebay.py` parser with region-specific DE + UK modules.
The previous parser's regex tried to extract `sold_date` from the item
page, but UK eBay item pages have no human-readable sold text (only a
JSON `endDate` data island) — 99% of UK rows had null `sold_date`. The
redesigned scraper extracts the date from the search-page green
"Sold D Mon YYYY" (UK) / "Verkauft D. Mon YYYY" (DE) text where it
actually lives.

### Deviations from the plan (logged in `log/M6.5-T1.md`)
- Real-world regex differs from the plan's regex (actual DE search HTML
  uses `<span class="su-styled-text positive default" aria-label="Verkaufter Artikel">`,
  not the plan's bare `aria-label="Verkauft...">`). UK uses
  `aria-label="Sold item"`. URL extraction anchors on
  `<a class="s-card__link"...>` to avoid picking up unrelated
  `ebay.com` promo hrefs.
- Card-id format `OP01-042` required dash-preserving title normalization
  (the plan's regex stripped the dash). Fixed by preserving dashes in
  the title then formatting the matched set+card with a dash before the
  last 3 digits (`OP01042` → `OP01-042`).
