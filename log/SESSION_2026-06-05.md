### M6.5-T2 — skip listings without a recognizable card_id (`9b524dc`)
The UK/DE item parsers' shared `_normalize_card_id()` returned the whole
normalized title as `card_id` when no `(OP|EB|ST|PRB|P)\d+` set code
matched. Real cases from the 2026-06-05 run: a 3-card bundle wrote
`OnePieceTCG2ndAnniversaryWinner3CardsLuffy...` and a DON energy card
wrote `PSA10DONCardCarryingOnHisWillFoilOnePieceTCG` — both into bronze,
SQLite, and silver/quarantine.

Fix: `_normalize_card_id` returns `('', None)` on no match; parsers
return `[]` when `card_id` is empty, skipping at parse time. See
`log/M6.5-T2.md`.

### Pagination + multi-key Zyte rotation (`194cf4f`)
Two infrastructural changes that unblocked long historical backfills:

1. **Pagination.** UK and DE scrapers now iterate through all available
   eBay search result pages (`_pgn=1,2,3...`) until eBay returns an
   empty page. Stop condition is `0 total pairs` — never stop on `0 new
   items`, so we skip past fully-already-scraped pages to reach newer
   history behind them. Idempotency is per-item within each page
   (`already_seen` grows monotonically), so the loop converges.

2. **Multi-key Zyte rotation.** `ZyteSessionResource` now reads
   `ZYTE_API_KEY1`, `ZYTE_API_KEY2`, ... from env at init time, creates
   one `ZyteAPI` client per key, and rotates on exhausted retries. On
   429 or transient error, retries with backoff on current key; if all
   retries exhaust, moves to next key. If all keys fail, raises
   `RuntimeError` listing the exhausted keys. Extend by adding
   `ZYTE_API_KEY3` etc. to `.env`.

### Skip per-item Zyte fetches for already-seen pages (`d231358`)
eBay's sold search results don't follow strict chronological order on
later pages — old items get mixed in. When paginating back through
history, the scraper was fetching search pages, parsing all items, then
doing 1 Zyte call per item only to skip them all via `already_seen`.

Two changes:
1. After parsing a search page, compute the set of item_ids on the page
   and intersect with `already_seen`. If the intersection equals the
   full set, skip the per-item loop entirely and go straight to the
   next search page.
2. Track `empty_streak` across consecutive all-already-seen pages. After
   5 in a row, stop scraping — history is fully scraped. Both checks
   log: `Page N: all X items already seen (streak K/5)`.

### Atomic SQLite write per item (`98a93e3`)
Scrapers wrote to MinIO during the per-item loop but the SQLite write
was deferred to `bronze_ebay_*_sqlite_writer` which only ran after the
entire scraper completed. For long backfills, eBay shows the same
item_id on multiple pages and the stale `already_seen` meant we'd
re-scrape it (1 Zyte call + 1 MinIO overwrite) without ever recording
it in SQLite.

The interrupted run on 2026-06-05 hit exactly this: 38-39 new items
written to MinIO across pages 1-36, scraper interrupted before the
writer ran, SQLite stayed at 65 records. Next run would re-scrape them.

Fix: after each MinIO `put_object`, `INSERT OR IGNORE` into `fact_events`
with `parqueted=1`. Update `already_seen` in the same iteration. The
downstream writer still runs but becomes a no-op safety net
(`INSERT OR IGNORE` on `(card_id, source_url)` PK). Net effect: within
a single run, the second time eBay shows the same item_id, `already_seen`
has it and the per-item Zyte fetch is skipped.

### Failed-parse streak circuit breaker (`a273fbf`)
Pages where ALL items fail to parse (M6.5-T2 skips them with empty
card_id) were not triggering any circuit breaker — `new_item_ids` was
non-empty so the skip-already-seen check never fired, and the per-item
loop kept iterating but found only garbage-card-id items that returned
`[]` from the parser.

Added `empty_parse_streak` counter: tracks pages where zero items were
successfully written. After 5 consecutive pages with no writes, stops
with a clear log message. Resets when any page has at least one
successful write. Stop log:
`Stopping: 5 consecutive pages with no successfully parsed items — eBay may only be showing unparseable listings`.
