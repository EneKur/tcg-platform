# Session Log — 2026-06-08

## What was done

Fixed the 1,042 / 1,225 CDN 403 failures from the `sync_card_images_job`
that the user noticed in the `dg dev` terminal on 2026-06-07.

### Root cause (two distinct bugs, both rooted in the same assumption)

The original `sync_card_images` was passing the *container set* (the set
whose page the card was scraped from) to `build_cdn_url` as the set
directory. The Limitless CDN layout uses the *card's home set* (the
prefix encoded in the card_id). For most base cards these match, so
the bug was invisible in tests; for cross-set reprints and set-name
alias slugs it was not.

**Bug 1 — cross-set reprints.** Cards like `EB02-001` are reissues of
earlier-set cards. Limitless links them from the reissuing set's page
(e.g. OP16's page links to `ST15-005?v=4`, `OP10-045?v=2`,
`EB01-003?v=3`). The CDN image lives at the card_id's home prefix path
(`ST15/ST15-005_p4_EN.webp`), not the container path
(`OP16/ST15-005_p4_EN.webp`). 177 / 200 (88.5%) of a sampled failure
bucket were this case — each one had a working URL available, just at
the wrong path.

**Bug 2 — set-name alias slugs.** Limitless's set pages contain links
like `/cards/OP16-THE-TIME-OF-BATTLE` and `/cards/ST30-EX-LUFFY-ACE`
that are set-page aliases (the set's display name slugged). They match
the OP/EB/ST prefix regex used by `extract_card_links_from_set_page`
but have no CDN image at all — confirmed by probing 24 candidate paths
and the cards' own pages (which redirect to the set page). 23 / 200
(11.5%) of the sampled failures were this case.

### Fix

In `src/tcg_platform/scraping/limitless_sync.py`:

- New helper `home_set_from_card_id(card_id)` — strict regex
  `^(OP|EB|ST|PRB|P)(\d{2}|[A-Z0-9]+)?-([A-Z0-9]{1,8})$`. The 8-char
  cap on the suffix is what rejects the alias slugs. Raises `ValueError`
  on malformed input (catches the alias slugs and any future drift).
- New helper `is_real_card_id(card_id)` — boolean wrapper, used by
  `extract_card_links_from_set_page` to filter at the scrape layer.
- `build_cdn_url(card_id, variant)` and `build_minio_key(card_id, variant)`
  now take `(card_id, variant)` instead of `(set_code, card_id, variant)`
  and derive the set directory from the card_id prefix.
- `build_card_image_diff` returns `(card_id, variant, minio_key)`
  3-tuples (was 4).

In `src/tcg_platform/scraping/limitlesstcg.py`:
- `extract_card_links_from_set_page` calls `is_real_card_id` and skips
  the alias slugs. The two new tests (`test_filters_set_name_alias_links`,
  `test_keeps_short_named_promos`) pin this behavior — both real
  promos like `P-105` (4-char suffix) and phantom `OP16-THE-TIME-OF-BATTLE`
  (20-char suffix) are covered.

In `src/tcg_platform/defs/discover_limitless_catalog.py` and
`sync_card_images.py`:
- Asset signatures and loop unpacking updated to the new tuple shape.
- No other behavior change; the upstream helpers own the home-set
  derivation.
