# M7-T1 Log: Silver Layer with LakeSail (pysail)

**Date:** 2026-05-28
**Status:** ✅ Complete

## Summary

Built the silver layer using LakeSail (pysail) as the Spark-like compute engine. Two Dagster assets (`silver_de_transform`, `silver_uk_transform`) read bronze parquets from `tcg-bronze`, validate card_ids against the cardlist in `tcg-bronze/cards/`, and write outputs to `tcg-silver`.

## Architecture

```
tcg-bronze/
  cards/{set}/{card_id}.webp    ← cardlist (valid card_ids)
  sold_data/DE/{item_id}.parquet  ← bronze input
  sold_data/UK/{item_id}.parquet

tcg-silver/
  data/de/data.parquet           ← valid records (card_id found in cardlist)
  data/uk/data.parquet
  quarantine/de/data.parquet     ← invalid records (no valid card_id)
  quarantine/uk/data.parquet
```

## Transformation Logic

For each bronze parquet row:
1. Extract card_id via regex `(OP\d+|EB\d+|ST\d+|PRB\d+)` from the raw `card_id` field
2. Check if it has a number component (ST10 alone = set code only, not a complete card)
3. Normalize 5-digit IDs: `ST13003` → `ST13-003`, `OP07029` → `OP07-029`
4. If normalized ID exists in `tcg-bronze/cards/` → write to `data/`
5. If no match → write to `quarantine/`

## LakeSail Integration

**Pattern:** Start `SparkConnectServer` in asset, connect via `SparkSession.builder.remote("sc://localhost:{port}")`.

```python
server = SparkConnectServer("127.0.0.1", 0)
server.start(background=True)
port = server.listening_address[1]
spark = SparkSession.builder.remote(f"sc://localhost:{port}").getOrCreate()
# ... run transforms ...
server.stop()
```

**Dependencies added to pyproject.toml:**

- `pyspark>=4.1.0` — Spark Connect client

## Key Implementation Details

### Normalization

| Raw extracted | Normalized | Example match |
|---------------|------------|---------------|
| `ST13003` | `ST13-003` | cardlist has `ST13-003.webp` |
| `OP07029` | `OP07-029` | cardlist has `OP07-029.webp` |
| `ST08005` | `ST08-005` | cardlist has `ST08-005.webp` |
| `ST10` | `ST10` | set code only → quarantined (no number) |
| `OP01` | `OP01` | set code only → quarantined |
| `EB01-001` | `EB01-001` | already normalized → matches |

**Bug fixed during dg dev:** `minio_client` was listed both as `required_resource_keys={"minio_client"}` AND as a function parameter. Dagster treated the parameter as an upstream asset dependency, causing `Input asset "["minio_client"]" is not produced by any of the provided asset ops`. Fixed by removing `minio_client` from the function signature and accessing it via `context.resources.minio_client` inside the function.

### Idempotency

Each asset run overwrites `data/{region}/data.parquet` and `quarantine/{region}/data.parquet`. Re-running picks up any new bronze parquets written since last run.
