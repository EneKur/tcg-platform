## Original Intent

Create Dagster schedules for the scraping pipelines:
- **Daily full refresh** — re-scrape all available listings
- **Hourly incremental** — only new listings since last run

## Current State

Incremental scraping is implemented at the asset level:
- `sqlite_client.get_seen_ebay_item_ids()` — extracts already-scraped item IDs
- `scrape_ebay_listings()` skips any item_id in the seen set

But no Dagster `Schedule` objects exist. The pipelines are run manually via `dg dev` or triggered by backfill sensors.

## What Would Be Needed

1. **`Schedule` definitions** for `ebay_de_pipeline`, `ebay_uk_pipeline`, `ebay_eu_pipeline`
2. **Hourly incremental** — use `start_window` / `end_window` to query only recent sold listings
3. **Daily full** — re-scrape everything, let idempotency handle deduplication

## Blocker

None — implementation is straightforward. The ZyteSessionResource, SQLite resource, and asset logic all support this. Just needs `dg.schedule` decorator additions to `definitions.py`.
