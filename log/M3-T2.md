# M3-T2 Log: Inline Per-Item eBay Parquet Writer

**Date:** 2026-05-27
**Status:** ✅ Complete

## Summary

Implemented inline per-item parquet writing for eBay sold listings directly in the scrape loop of `ebay_de_sold_listings` and `ebay_uk_sold_listings`. Each scraped item is written to MinIO as a single-row Parquet file immediately after parsing — no separate aggregation step needed.

## Design

Per `2026-05-27-sold-data-parquet-design.md`:

```
For each scraped item_id:
  ├─── scrape item → parse PriceRecord
  ├─── image → MinIO sold_images/{region}/{item_id}.jpg
  └─── parquet → MinIO sold_data/{region}/{item_id}.parquet  ← new, inline
  └─── pass record to sqlite_writer (batch insert)
```

## Storage Paths

| Path | Format |
|------|--------|
| `sold_data/DE/{item_id}.parquet` | Single-row Parquet per DE eBay item |
| `sold_data/UK/{item_id}.parquet` | Single-row Parquet per UK eBay item |

## Implementation

Uses existing `price_records_to_parquet()` from `tcg_platform/serialization/card_parquet.py`. Writes happen inline in the scrape loop at lines 76-85 of both `ebay_de_sold_listings.py` and `ebay_uk_sold_listings.py`.

`bronze_sold_data_parquet.py` (standalone asset) was **removed** — inline approach replaces it.

## Files Changed

- `src/tcg_platform/defs/ebay_de_sold_listings.py` — added parquet write inline
- `src/tcg_platform/defs/ebay_uk_sold_listings.py` — added parquet write inline

## Backfill

`backfill_sold_data_parquet.py` provides a backstop asset + sensor that catches any records that somehow missed the inline write (queried via `get_unparqueted_fact_events`). Runs automatically after each successful pipeline run via `backfill_de_sensor` / `backfill_uk_sensor`.
